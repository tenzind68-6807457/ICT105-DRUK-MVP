# Slide 2 — The Problem and Target Users

## Target Users

### Primary Users

- First-year undergraduate students
- International students
- Exchange students

### Secondary Users

- Student clubs
- Event organizers
- Campus administrators

## Problem

Campus event information is currently scattered across:

- Social media
- LINE groups
- Email announcements
- University websites
- Posters around campus

This causes:

- Students missing important events
- Difficulty finding event information
- Confusing registration processes
- Lower student participation

## Customer Discovery

Our interviews and surveys found that students wanted:

- One centralized platform
- Easier event discovery
- Search and filtering
- Online registration
- Personal event management

**Speaker Point**

The problem is not the lack of campus events—it is the lack of a centralized system that helps students easily discover and participate in them.

# Suggested Q&A Preparation

### Why not use social media?

Social media announcements are scattered and unstructured. Smart Campus Event Hub centralizes event information, registration, dashboards, and event management in one platform.

### Is the login secure?

The current version is a classroom MVP using browser localStorage. A production system would include secure authentication, server-side processing, and encrypted passwords.

### How does the system benefit students?

Students can quickly discover events, register online, manage participation, and submit feedback without searching across multiple communication channels.

### How can the project grow in the future?

Future development includes university authentication, cloud databases, QR attendance, push notifications, analytics dashboards, and a mobile application.

### What evidence supports the project?

The project is supported by customer interviews, surveys, customer validation, usability testing, startup metrics, GitHub development history, and successful completion of the minimum functional and technical requirements defined in the system requirements.
